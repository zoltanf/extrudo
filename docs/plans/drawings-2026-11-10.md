# Drawings: 2D sheets made from the model (plan and specification, 2026-11-10)

**Status:** accepted by the owner on 2026-11-10, every decision of §12 as proposed; nothing
is built. Asked for by the owner the same day with six printed sheets from an established
desktop CAD tool as the reference for what a drawing is. Recorded as **ADR-0143**; the task
is **P6-24** in `docs/03-roadmap.md` and the requirements are FR-DR-01 to FR-DR-08 (until
this plan, "2D engineering drawings" stood under *Out of scope*). This file stays the
detailed specification the slices work from; a slice that departs from it says so in an
amendment to the ADR. Code pointers are against `main` at `aded5cc7`; "today" marks what the
code does now.

**Mock-ups:** five pages beside this file, "artboard 1" to "artboard 5" below:
`drawings-mock-1-mode.html` (the drawing mode), `drawings-mock-2-entry.html` (getting there
from the model), `drawings-mock-3-dimension.html` (the Dimension tool, light theme),
`drawings-mock-4-export.html` (the export dialog) and `drawings-mock-5-concepts.html` (the
three shell concepts). They are the sources of a design canvas (hence the `x-dc` wrapper
and the `support.js` line: that file is not in the repository, so its load fails and
nothing runs) and open as plain pages: straight from
disk, or through `pnpm dev` at `http://localhost:5173/@fs/<absolute path>`. Screens 1 to 3
are drawn for a 1440 × 900 window.

## 1. What the reference sheets hold, and what we take from them

Six pages for a built-in cabinet and its base frame:

| On the sheets | We take it as |
|---|---|
| Orthographic views of chosen bodies (front, side, top), one view shaded | views with a direction, a scale, a style and a body list |
| Linear dimensions: horizontal, vertical, aligned to a slope, chained | associative dimensions measured from the model |
| Whole millimetres on some sheets, two decimals on others | decimals per sheet, overridable per dimension |
| Dash-dot centre lines | centre lines and centre marks |
| Balloons (a number in a circle with a leader) and a parts list with item, quantity, name, material and board sizes | balloons tied to a parts list; a **Size** column from each body's bounding box |
| A title block (title, author, date, sheet n/N and more) and a border with zone letters | title block templates; the zone border is optional |
| A3 and A4, portrait and landscape | sheet sizes and orientation per sheet |
| Handwritten corrections and a paper sticky note | text notes, leader notes and **sticky notes** that stay out of the print by default |

**Goals.** A person who modelled something can, in a few minutes, get printable sheets that
show it with dimensions and a parts list, and the sheets stay right when the model changes.
One file (`.extrudo`), one undo history, export to PDF.

**Not goals.** Compliance with a drawing standard (we follow the conventions people expect,
we do not claim ISO or ASME conformance); GD&T, weld and surface symbols; 2D drafting
without a model; editing the model by changing a drawing dimension (dimensions are measured,
never driving).

## 2. Words

The word *drawing* is taken three times today: **Import Drawing** (SVG/DXF into a sketch,
ADR-0066), the `Drawing` type of `packages/io/src/drawing.ts` (the neutral 2D model behind
`writeSvg`/`writeDxf`), and a local `drawing` flag in `AppShell.tsx` (a sketch drawing tool
is running). ADR-0126 met the same problem with "annotation" and renamed the older use.

**In the interface** the feature is **Drawing** (the mode, the tab, "New drawing",
"Finish Drawing") and a page is a **sheet**. **In code** the noun is always `sheet`
(`doc.sheets`, `SheetSchema`, mode `'sheet'`, `apps/web/src/sheets/`), so no identifier
collides. Import Drawing is renamed **Import SVG/DXF** when the mode lands (decision 3; the
label in `tools.ts`, the guide and the specs that name it).

| Word | Meaning |
|---|---|
| sheet | one page: a size, an orientation, a border, a title block and items |
| view | a picture of bodies on a sheet. **Base view**: direction chosen freely. **Projected view**: made from a base view, stays aligned with it and takes its scale and style |
| item | anything else placed on a sheet: dimension, centre mark, centre line, text, leader note, balloon, sticky note, parts list, table |
| anchor | where an item is tied to the model: a `GeomRef` with a fingerprint (ADR-0005), as annotations use |
| detached | an item whose anchor no longer resolves; it is kept and drawn in the error colour |

## 3. Where it lives: a mode, like a sketch

Three concepts were drawn (artboard 5):

- **A. A mode, like a sketch (chosen, decision 2).** Entering it swaps the tabs to `HOME` + `DRAWING`,
  the 3D view for the sheet, and the timeline for sheet tabs. **Finish Drawing** returns to
  the model. It is the pattern the app already teaches, and it adds no permanent chrome.
- **B. A Model / Drawing switch in the top bar.** More toolbar room (several drawing tabs),
  but it is the workspace switcher that was removed on 2026-09-27 (`04-ui-spec.md` §2).
- **C. Its own window or route.** Good on two screens. Two shells to keep in step, a second
  save state to explain, and the web app has no window management. It can come later as
  "pop out" on the desktop without changing the model below.

### 3.1 What each part of the shell becomes

| Region | Model | Sketch (today) | Drawing |
|---|---|---|---|
| Tabs | Home, Solid, Modify, Construct, Make | Home, Sketch | Home, **Drawing** |
| Toolbar end | — | Finish Sketch | **Finish Drawing** |
| Browser | the design's tree | the same, sketch marked "editing" | **Sheets** tree (sheets › views, dimensions, notes, parts list, title block), then **Bodies** |
| Centre | 3D view | 3D view on the sketch plane | the **sheet** (2D, SVG; no WebGL) |
| Right column | feature dialog, tool panels | sketch palette, tool panels | properties of the selection, or the running tool's panel, or the sheet's setup |
| Floating bar | navigation, visual style, grid | the same | select, pan, zoom, fit, zoom %, snap, sticky notes on/off |
| Bottom row | timeline + status | timeline (locked) + status | **sheet tabs** + status |
| ViewCube | shown | shown | hidden |

Home's model-only tools (Import, Canvas, Customizer) say "Finish the drawing to use …", as
they do in a sketch. **Parameters stays available**: changing a value in drawing mode
recomputes the model and the views follow, which is the quickest way to see that a drawing
is alive.

### 3.2 Getting in and out

- **Make › Output › Drawing** (a new tile beside Render Picture; artboard 2). With no sheets
  it opens **New drawing**; with sheets it opens the one edited last.
- **Browser › Drawings** in the model (below Annotations; always shown, "No sheets yet"
  when empty, like Sketches): one row per sheet; double-click or Enter opens it, the row
  menu has Open, Rename, Duplicate, Export, Delete.
- **Ctrl+K**: "New Drawing", "Open Drawing", `Sheet: <name>`.
- Out: **Finish Drawing** (the tile or the panel's button). Esc ends a tool, then clears the
  selection; it never leaves the mode. Nothing is asked on the way out: every edit is
  already in the document (decision 13).
- Entering ends an open sketch or feature dialog first, as version restore does.

### 3.3 Which model the sheets show

Views show **the bodies at the timeline marker**, as export and Measure do today (the
kernel keeps results only at the marker: `RecomputeEngine`'s `#latest`). With the marker
rolled back the status bar says so ("Showing the model at feature 5 of 7"). The CLI uses the
document's saved marker.

### 4.2 The sheet

- **Paper is white in both themes** (decision 5): the sheet is what the PDF will be. It lies
  on the viewport glow with a shadow. Lines are black: visible 0.5 mm, hidden 0.25 mm
  dashed, dimension and centre lines 0.18 mm (all in sheet settings).
- **Navigation:** pan and zoom with the chosen mouse preset's own pan and zoom bindings
  (the wheel zooms at the pointer), `F6` fits the sheet as it fits the model. No orbit.
- **Select** (no tool): hover pre-highlights in the preselect tint; click selects (Shift/Ctrl
  toggles), a drag on empty paper box-selects, Delete deletes, arrow keys nudge by the snap
  step. A view shows a dashed accent frame and a name tag when selected. Dragging moves an
  item; a projected view moves only along its alignment axis (Alt breaks the alignment).
  Double-click edits text in place, opens a dimension's text, or opens a view's properties.
- **Snap:** items snap to each other's edges and centres and to dimension rows (an even
  10 mm between stacked dimension lines), with the sketch's dashed guides. One switch.
- **Right-click:** the item's menu (Edit, Hide, Bring forward, Delete; for a view also
  Projected View from This, Fit Scale, Align; for a dimension Edit Text, Decimals).
- **While the kernel works** a view keeps its last lines, dimmed, and the wait is reported
  the way other kernel waits are (ADR-0105); a first-time view shows its frame and "Drawing
  the view…". Cancel (ADR-0111) leaves the old lines.

### 4.3 The right column

One card, as wide as the sketch palette, whose content follows the state:

- **Nothing selected:** the sheet's setup (name, size, orientation, default scale, decimals,
  title block fields) and **Finish Drawing**.
- **A view selected** (artboard 1): Looking from (Front, Back, Left, Right, Top, Bottom,
  four isometrics, the model's current view, each named view), Scale (the sheet's, or
  1:1, 1:2, 1:5, 1:10, 1:20, 1:50, 2:1, 5:1, or custom), Style (visible edges; visible and
  hidden; shaded; shaded with edges), switches for hidden lines, tangent edges, centre
  lines and the view label, and the bodies as checkboxes ("All shown" follows the model's
  eyes). A projected view shows its parent and has only its own label and visibility.
- **A dimension selected:** decimals, text before and after, brackets (reference), the
  direction (auto, horizontal, vertical, aligned), arrows inside or outside.
- **A tool running** (artboard 3): the tool's panel, with what to pick next.

Every number field is an `ExpressionInput` (hard rule), so `width / 2` works as a custom
scale's part or a text height; sheet layout stores the **evaluated number** (§5.3).

### 4.4 Sheet tabs

The bottom row's left side: one tab per sheet with a small page icon in the sheet's
orientation and "n · name"; the current one in the accent. Click switches, drag reorders,
double-click renames, `+` adds, the menu has Duplicate, Export This Sheet, Delete.
`Ctrl+PageUp/PageDown` switch. The status text and the bell stay on the right.

### 4.5 Flows

- **New drawing** (artboard 2): Start with **Standard views** (front, top, side and an
  isometric, laid out for the chosen projection and scaled to the largest standard scale
  that fits), **One view**, or **Empty sheet**; sheet size and orientation; title block;
  bodies; first or third angle (decision 10). One undo step, "New drawing".
- **Base View:** the panel shows the choices; a frame of the view's size follows the pointer;
  a click places it. The tool then continues as Projected View from it until Esc.
- **Projected View:** pick a view, move away from it: right/left/up/down give the
  neighbouring orthographic view for the sheet's projection angle, a diagonal gives an
  isometric. Click places; repeat; Esc ends.
- **Drag a body** from the browser onto the sheet: a base view of that body alone, front,
  sheet scale.
- **Dimension:** hovering highlights what a click takes (edge, vertex, circle, centre line);
  after the picks the dimension follows the pointer in the preview colour with its value; a
  click places it. It stays on until Esc. A value is `measured × 1` in document units; the
  unit is shown only if switched on.
- **Parts List:** click a view, then place the table. Rows are the view's bodies, identical
  bodies merged into one row with a quantity (same component name or same name stem and
  equal volume and bounding box). Columns: Item, Qty, Name, Material, Size, Mass; any can be
  hidden. Balloons take their numbers from it.
- **Sticky Note:** click, type, Enter. Yellow by default, five colours. It carries "On
  screen only" until its **Print** switch is on; the export dialog counts those left out.
- **Export** (artboard 4): sheets as checkboxes, format (PDF first; SVG and PNG one file per
  sheet; DXF later), black or as on screen, selectable text, sticky notes, file name; a
  summary line; `files.download`. Format and switches are remembered in preferences.

### 4.6 States and messages

| State | What the person sees |
|---|---|
| A view's body was deleted | the view keeps its frame, empty, with "Box is gone. Choose bodies or delete the view." |
| An anchor is lost | the item in the error colour, dashed, a ⚠ in the browser row; status bar: "This dimension lost its edge: drag an end onto an edge, or delete it." |
| An anchor resolved by fingerprint | drawn normally, ⚠ warning in the browser row ("moved"), as annotations do |
| A mesh body in a view (first version) | not drawn; the view says "Mesh bodies can't be drawn yet." |
| A hidden body | "All shown" views drop it; a view with chosen bodies keeps it |
| No WebGL 2 | drawing mode works for line views; shaded views say why they are empty |

## 5. The document

### 5.1 Shape

One new optional top-level key, `sheets`, after `annotationCounter`. Additive: no
`formatVersion` bump and no migration (`docs/file-format.md` §3), an older reader drops the
key and reports it. A sketch of the types (names and details settle in S1, as an amendment
to ADR-0143):

```ts
sheets?: Sheet[]                       // in page order; absent when there are none

interface Sheet {
  id: SheetId;                         // newId() in the caller
  name: string;                        // unique among sheets
  size: 'A4' | 'A3' | 'A2' | 'A1' | 'A0' | 'letter' | 'legal' | 'tabloid' | [w: number, h: number]; // mm
  orientation: 'landscape' | 'portrait';
  scale: [number, number];             // the sheet's default, e.g. [1, 2]
  projection: 'first' | 'third';
  decimals: number;                    // 0..4, for dimensions
  border?: { zones?: true };           // absent: no border
  titleBlock?: { template: 'simple' | 'full'; fields: Record<string, string> };
  views: SheetView[];
  items: SheetItem[];                  // drawn in order
}

interface SheetView {
  id: SheetViewId;
  name: string;                        // "Front"; unique in the sheet
  at: Vec2;                            // the view's origin on the sheet, mm from the top-left
  from: { direction: Vec3; up: Vec3 } | { parent: SheetViewId; side: 'left' | 'right' | 'above' | 'below' | 'iso-…' };
  scale?: [number, number];            // absent: the sheet's (a projected view never has one)
  style?: 'visible' | 'hidden' | 'shaded' | 'shaded-edges';   // absent: 'hidden'
  bodies?: BodyId[];                   // absent: every shown body
  tangentEdges?: false; centreLines?: false; label?: true;
}

type SheetItem =
  | { kind: 'dimension'; id; view: SheetViewId; type: 'linear' | 'radius' | 'diameter' | 'angle';
      direction?: 'horizontal' | 'vertical' | 'aligned'; anchors: SheetAnchor[]; at: Vec2;
      decimals?: number; before?: string; after?: string; reference?: true }
  | { kind: 'centreMark' | 'centreLine'; id; view; anchors: SheetAnchor[] }
  | { kind: 'text'; id; at: Vec2; text: string; size?: number; width?: number }
  | { kind: 'leader'; id; view; anchor: SheetAnchor; at: Vec2; text: string }
  | { kind: 'balloon'; id; view; anchor: SheetAnchor; at: Vec2; list: SheetItemId }
  | { kind: 'sticky'; id; at: Vec2; size: Vec2; text: string; color?: string; print?: true }
  | { kind: 'partsList'; id; view; at: Vec2; columns?: string[];
      rows?: Record<BodyId, { name?: string; material?: string }> }   // what was typed over a row
  | { kind: 'table'; id; at: Vec2; columns: number[]; rows: string[][] };

type SheetAnchor =
  | { ref: GeomRef; at?: 'start' | 'end' | 'middle' | 'centre' }   // vertex, edge, circle centre
  | { ref: GeomRef; silhouette: 1 | -1 }                            // a cylinder's or cone's outline
  | { free: Vec2 };                                                  // view coordinates, not tied
```

Rules: every `ref` has a fingerprint and is never an `index:` ref (as `AnnotationSchema`
requires); ids and names unique (rows in `DocumentSchema`'s `unique` table); a `parent`, a
`view` and a `list` name something that exists in the same sheet (`reportSheets`, like
`reportAnnotations`).

### 5.2 Commands and cascades (`packages/core/src/sheets.ts`)

`addSheet`, `updateSheet`, `removeSheet`, `moveSheet`, `addSheetView`, `updateSheetView`,
`removeSheetView` (removes the view's items and its projected children, one step),
`addSheetItem`, `updateSheetItem`, `removeSheetItems`. Recipes are deterministic; ids come
in the payload.

The annotations commit (`d9515278`, ADR-0126) is the checklist; the same places need sheets:

- `restoreVersion` (`document-commands.ts:60`) copies each collection by name: add `sheets`.
- `remint.ts`: rewrite anchor refs and body ids when features are copied.
- Removing a feature leaves anchors to detach at the next resolve (never refuse a delete).
- The documents a Script feature and plugin commands see drop `annotations`; drop `sheets` too.
- `docs/file-format.md` (a new §4.11, the key table, the additive list) and
  `packages/storage/src/file-format-doc.test.ts` (the sub-schema key list is by hand);
  an "older reader" test in `migrations.test.ts`.

### 5.3 Numbers, text and what is not stored

- Layout numbers (positions, sizes, scales, decimals) are stored as **numbers**. Fields
  accept expressions and store the result, so no parameter rename can break a sheet and
  `rewriteReferences` needs no new entry in S1–S4.
- Text may hold **fields in braces** from S5: `{name}` (the design), `{sheet}`, `{sheets}`,
  `{scale}`, `{date}`, `{version}` (the newest saved version, ADR-0036), and `{= expr}` for
  a parameter expression (`{= clearance}` prints `0.2 mm`). `{= …}` holds parameter names,
  so `rewriteReferences` then covers sheet text.
- **Nothing derived is stored**: no projected lines, no measured values. Opening a file
  recomputes its views. (`cache/` in the container is reserved by the format doc and unused;
  it stays unused.)
- **The author's name** is not in the document today and is not added silently: "Drawn by"
  is a title-block field that is empty until typed; the last typed value is remembered as
  an app preference and offered, never written by itself (the repository rule on personal
  data applies to shared designs too).
- **Material** is not in the document either (the filament is an app preference,
  `print.material`). Decision 11: the parts list's Material column is free text per row in
  the first release; `BodyMeta.material?: string` stays a possible later addition.

## 6. Geometry: from bodies to lines

### 6.1 Today

- The facade's `edgeVisibility(shape, direction)` (`extrudo_facade.cpp:~2049`,
  `Kernel.edgeVisibility` at `kernel.ts:1821`) runs `HLRBRep_Algo` and returns **one flag
  set per edge**: some of it visible, outline, sharp. It walks the visible spans with
  `HLRAlgo_EdgeIterator.InitVisible` but returns only whether any exist.
- `edgeGeometry` gives an edge as an exact line, circle or ellipse (else samples);
  `faceSilhouettes` gives a face's outline curves for a direction (closed form for cylinders
  and cones, `Contap_Contour` otherwise); `sectionWithPlane` gives exact cut curves.
- `packages/kernel/src/features/projection.ts` and `projectBody` in `features/sketch.ts`
  map those through a frame into exact 2D lines, arcs, ellipses and splines. That is a
  **visible-lines-only** view from any direction, used by a sketch's Project.
- No worker call returns a 2D view (`KernelApi` in `service.ts`), and results exist only
  for the bodies at the marker. Mesh bodies refuse every one of these calls.
- Hidden-line removal is in the shipped WASM already (`edgeVisibility` uses it), so spans
  need a facade change but no new OCCT library.

### 6.2 What to build

1. **Spans, not flags.** A facade method beside `edgeVisibility` that returns, per edge of
   the HLR data (model edges and the outlines HLR adds), the visible parameter intervals and
   the edge's kind; hidden is the complement. Staged flat arrays, ints and doubles only, as
   ADR-0001 requires; a new OCCT input hash and a CI build. **Spike first (S0):** time it on
   the benchmark models B1–B10 and on a 200-face assembly, check the heap, and compare
   against `HLRBRep_HLRToShape` (compiled in the toolchain, not referenced today) before
   choosing.
2. **A view evaluator** in `packages/kernel/src/sheets/` (TypeScript, Node-runnable): frame
   from direction and up (a projected view derives its frame from its parent and the sheet's
   projection angle), then `ViewGeometry`:

   ```ts
   interface ViewGeometry {
     curves: { kind: 'visible' | 'hidden' | 'outline' | 'tangent'; edge?: string /* topo name */;
               pieces: CurvePiece[] /* line, arc, ellipse, polyline; view mm at model scale */ }[];
     bounds: Bounds;
     status: 'ok' | 'partial';           // partial: a body was skipped (mesh, gone)
   }
   ```
   It reuses `projection.ts`; every OCCT handle is scoped (`kernel.scope()`).
3. **A worker call**, `sheetViews(requests)`, against the bodies at the marker (`#latest`),
   cancellable and reported like other waits (ADR-0105, ADR-0111). **Cache** in the engine,
   keyed by the bodies' version hashes, the direction, up and the options; scale and
   position are applied on the UI side so moving or rescaling a view costs nothing.
4. **Anchors.** A second call, `resolveSheet(sheet)`, resolves every anchor like the
   annotation pass (`resolveRef`: exact name, related name, fingerprint; `ok`, `moved`,
   `detached`; never failing a recompute) and returns the 3D geometry each needs (a point; a
   line's ends; a circle's centre, axis and radius; a silhouette's two lines). The UI
   projects them through the view frame and computes the value. A lost anchor keeps its last
   resolved sheet position so the item stays where it was, drawn as detached.
5. **Picking** for the Dimension tool uses the view's curves: each carries its edge's
   topological name, so a click becomes a `GeomRef` through `KernelApi.reference`, and
   vertices come from curve ends. Outline curves of cylinders and cones become `silhouette`
   anchors; other outlines (spheres, free-form) are not dimensionable in the first version.
6. **Shaded views** (later): `viewport.snapshot(size, {view, bodies})` already renders a
   body subset from a camera of its own; a shaded view is that picture under the HLR lines.
   It needs WebGL and gives a raster in the PDF.

## 7. Drawing it: one display list, three outputs

A sheet is turned into a **display list** (paths with a width, dash and fill; text runs;
pictures; all in sheet mm) by pure code, and three consumers draw it: the screen (SVG in the
DOM), `writePdf` and `writeSvg`. What is on screen is what is exported.

- **New package `@extrudo/sheets`** (GPL like core; depends on `core`, `sketch`, `io`,
  `fonts`; no DOM; runs in Node): layout of dimensions (extension lines, arrows, text placement; the
  sketch's `dimensionLayout.ts` is the model), tables, the title block and border, view
  labels, field substitution, and the display list. Add it to `scripts/check-boundaries.mjs`.
- **`@extrudo/io`** (MIT) gets the display-list types and **`writePdf(pages)`**, our own
  small writer in the tradition of `writeSvg`, `writeDxf` and `xml.ts`: PDF 1.4, one page
  per sheet at its true size, vector paths, deflate through `fflate` (already io's
  dependency), pictures as JPEG or PNG streams. **Text is drawn as glyph outlines** (the
  path sketch text already takes: `placeText` in `packages/sketch/src/export/`), plus an
  invisible text layer in a base-14 font so the text can be selected and searched without
  embedding a font. Rejected for now: a PDF library (a new dependency of several hundred kB
  for features we don't use; decision 7).
- **Font:** Inter Regular and Bold from `packages/fonts` (bundled, OFL; the subset has Ø, °
  and ±). The mock-ups show Instrument Sans, which is the UI font and not in that package.
  `opentype.js` may be imported only inside `packages/sketch/src/text`; `@extrudo/sheets`
  asks for outlines through that module's API.
- **Screen:** `apps/web/src/sheets/SheetCanvas.tsx` draws the display list as SVG, one
  `<path>` per view and line kind; selection, handles, previews and snap guides are a second
  layer. Pan and zoom change one transform (no React render per frame, ADR-0102).
- **SVG and PNG** export come from the same list (PNG by rasterising the SVG in the
  browser). **DXF** of a sheet is later: R12 has no text or dimension entities as we write it.
- **CLI:** `extrudo export design.extrudo --format pdf [--sheet <name>]` through the same
  packages (the CLI may already depend on `kernel`, `io`, `fonts`).

## 8. What the shell needs first

Today "mode" is the literal `'model' | 'sketch'` in `SessionState` (`stores.ts:260`) and in
about 15 other signatures (`tools.ts:1169–1179`, `Toolbar.tsx`, `commands.tsx:80`,
`menuModel.ts`, `contextEntries.tsx`, `viewMenu.tsx`, `keymapStore.ts:17`,
`MarkingMenuEditor.tsx`, `tutorial.ts`, `anchor.ts`), and `AppShell.tsx` branches on it in
roughly 60 places. The Finish tile is drawn only when the tab's id is `sketch`
(`Toolbar.tsx:417`).

**A preparation PR with no behaviour change** (S1a): one exported `EditMode` type; a small
table per mode (tabs, default tab, keymap mode, marking slots, finish tool); the Finish tile
from that table; `enterMode`/`exitMode` beside the sketch setters. Then the drawing mode is
additions:

- `session.mode = 'sheet'` with `activeSheetId`; `apps/web/src/sheets/mode.ts` mirroring
  `sketch/mode.ts` (`openSheet`, `finishDrawing`).
- `<main>`: a lazy `SheetWorkspace` chunk in place of `Viewport` (the 3D view stays mounted
  and paused, because thumbnails and shaded views use its `snapshot`).
- `Timeline`'s row renders `SheetTabs` in the mode; `BrowserPanel` gets the sheet tree, and
  the model tree a **Drawings** folder.
- `TOOLS`/`TABS` entries, icons (`ICON_NAMES` + SVG files), `DEFAULT_KEYMAP`, a `sheet`
  keymap and marking-menu mode, generated tool pages (`pnpm docs:generate`), `tabs.test.ts`.
- Agent tools refuse document changes while `mode === 'sketch'`; sheets need no such guard
  (no open transaction, decision 13), but the tools must end drawing mode before a
  model screenshot.

## 9. API, CLI and agents

- **`@extrudo/api`:** `design.sheets`, `addSheet`, `sheet.addView`, `view.addDimension`, …,
  handles, an id prefix, emitter support (Export as Script writes sheets), `docs/api/`.
  Scripts refuse the calls like annotations (`packages/script/src/restricted.ts`).
- **CLI:** `info` lists sheets (name, size, views, items, detached count); `export --format
  pdf|svg`; `check` fails on detached anchors when asked (`--sheets`).
- **MCP (desktop):** `list_sheets`, `add_sheet` (with the standard-views start), `add_view`,
  `add_dimension`, `export_sheet` (PDF or a PNG the agent can look at). One undo
  transaction per change, as today's tools. An agent that can make and read a dimensioned
  sheet can check its own model's sizes.

## 11. Risks

- **HLR cost.** Exact hidden-line removal is the expensive part and runs per view
  direction. Mitigation: the S0 numbers decide; cache per direction; views update one by
  one with progress; scale and position never recompute.
- **Anchors on outlines.** Silhouettes have no topological name. The first version anchors
  only to edges, vertices and cylinder/cone outlines.
- **The shell.** `AppShell.tsx` is 3385 lines with mode checks throughout; S1a exists so the
  risky edit lands alone, with sketch mode's tests as the net.
- **PDF text.** Outlined text makes files larger and is not editable in other tools; the
  invisible layer keeps search working. Readers differ: S0 checks three.
- **Scope.** Drawing standards are deep. The non-goals in §1 are the line.

## 12. Decisions (the owner, 2026-11-10: all as proposed)

1. **Scope: 1.1.** "2D engineering drawings" leaves *Out of scope*; the task is P6-24 in
   Phase 6. (Not taken: a new phase after 6; not now.)
2. **Shell: 2.1, concept A,** a mode like a sketch. (Not taken: B, a Model/Drawing switch;
   C, its own window.)
3. **Names.** "Drawing" for the mode and "sheet" for a page, `sheet` in code. **3.2:**
   Import Drawing is renamed "Import SVG/DXF". (Not taken: keeping the name.)
4. **Sheets: 4.1, one flat list per design.** (Not taken: several named drawings, each with
   its sheets.)
5. **Paper: 5.1, always white.** (Not taken: following the theme, exported white.)
6. **First release: 6.2, S1 to S5:** sheets, views, dimensions, notes, parts list. S6
   follows. (Not taken: S1 to S3 alone.)
7. **PDF: 7.1, our own writer** with outlined text. (Not taken: a library.)
8. **Title block.** "Simple" by default (title, drawn by, date, scale, sheet, units,
   version), a fuller one optional; the author's name only when typed; the zone border off
   by default.
9. **Sticky notes: 9.1, not printed** unless a note's Print switch is on. (Not taken:
   printed by default.)
10. **Projection: 10.1, first angle** by default, chosen per sheet. (Not taken: third angle
    by default.)
11. **Material: 11.2, free text per row** of the parts list in the first release. (Not
    taken now: `BodyMeta.material`, a schema addition that Print Info could use too.)
12. **A new view** has hidden lines, tangent edges and centre lines on. (Not taken: hidden
    lines off for a cleaner first look.)
13. **Undo: 13.1.** Every sheet edit is its own undo step and Finish is not one: sheets are
    not timeline features, and parameters can change while drawing. (Not taken: one
    collapsed step per session, as a sketch.)
14. **Dimensions never drive the model.** "Double-click a dimension to edit the parameter
    behind it" was not asked for; it would be a decision of its own.
